### 2.1 环境（本机实测可用）

| 组件 | 路径 / 版本 | 备注 |
| --- | --- | --- |
| Python | `C:\Python310\python.exe`（3.10.11） | 只用标准库 + `backend/requirements.txt`；**没有 venv、没有 pytest**，测试用 `unittest` |

| 浏览器内核 | WebView2（系统已装） | `patchright` 另带一份 chromium，用于登录扫码与自动化 |

### 2.2 开发模式

```powershell
# 依赖（首次）
C:\Python310\python.exe -m pip install -r backend\requirements.txt

# ① 只起后端（前端没构建时给占位页）
cmd /c "set PYTHONPATH=.&& C:\Python310\python.exe -m backend.app.main --port 8080"

# ② 只起前端（Vite，热更新；请求代理到 8080）
cd frontend && npm install && npm run dev

# ③ 桌面窗口（推荐：自己起后端 + 开窗口 + 托盘）
cmd /c "set PYTHONPATH=.&& C:\Python310\python.exe desktop\main.py"
```

**`PYTHONPATH=.` 是必须的**（包名是 `backend.app.*`，不是相对导入），漏了会 `ModuleNotFoundError`。

### 2.3 打包

```powershell
# ① 先构建前端（js/css 文件名带内容 hash，任何前端改动都必须重跑）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build_frontend.ps1

# ② 再打包（PyInstaller，onedir）
taskkill /IM "闲鱼AI工作台.exe" /T /F        # ← 不先杀掉，打包必失败，见 §12
cmd /c "powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build_exe.ps1 -SkipFrontend > logs\build_exe.log 2>&1"

# ③ 起打包版（随便挑一个不冲突的端口）
Start-Process -FilePath "dist\闲鱼AI工作台\闲鱼AI工作台.exe" -ArgumentList "--port","18400"
Invoke-RestMethod -Uri "http://127.0.0.1:18400/api/health"     # {"success":true,"data":{"ok":true,...,"frozen":true}}
```

`-SkipFrontend` = 复用现有 `frontend/dist`。**注意**：`desktop/desktop.spec` 用
`collect_submodules('backend')` 收集模块，所以**连测试文件的改动都会进包** —— 只要改了
`backend/**`，就必须重打包，打包版复验才有意义。

### 2.4 数据目录与凭据

```
%APPDATA%\xianyu-ai-workbench\
  data\app.db                    SQLite（20 张业务表，DDL 直接在 `backend/app/core/db.py`）
  data\local_secret.txt          桌面免密密钥（外壳用它换 token）
  data\desktop_credentials.json  首次运行生成的管理员账号（随机密码）
  logs\app.log                   运行日志
  browser\                       扫码/自动化用的浏览器 profile
```

- 环境变量 `XIANYU_APP_DIR` 把整棵目录挪走（**测试与多实例全靠它**，跑测试时务必设成临时目录，
  否则会污染真实库）。
- 注意：`XIANYU_APP_DIR` 是**根**，数据在 `<root>\data`；`config.DB_PATH` 才是库文件路径

- 本地 API 需要 token：桌面外壳把 `xywb_token` 写进 localStorage。用脚本调接口的标准姿势：

```python

status, raw = call('POST', '/api/auth/desktop', extra={'X-Desktop-Secret': secret})

**分层规矩（改代码前务必接受）**：

```
api/*.py        只做三件事：取参数、调 service、套信封（common.respond / fail）
services/*.py   业务逻辑、闸门、日志、落库；协议层通过 common.get_client 懒导入

因为「协议层不可用 → 503 `xianyu_not_ready`」这条边界全靠 `common.get_client` 守住。

## 4. 四条关键链路

### 4.1 进程模型

```
闲鱼AI工作台.exe
  └─ PyInstaller 引导 → desktop/main.py
       ├─ 后端线程：uvicorn(FastAPI) 监听 127.0.0.1:<随机端口>（--port 可指定）
       ├─ 托盘图标（pystray）
       └─ PyWebView 窗口（WebView2）→ 加载打包好的 frontend/dist/index.html
            └─ 窗口就绪后把 token 注入 localStorage['xywb_token']
```

前端不轮询：后端有事件总线（`core/events.py`），前端用
`useAsync(loader, deps, immediate, topics)` 的**第 4 个参数**订阅话题，收到事件才重新拉数据。

### 4.2 买家发消息 → AI 回复

```
平台 IM 长连接/轮询 → xianyu/im.py 收帧
  → services/chats.py::handle_incoming      ← 判据链在这里（见 §5.6）
      ├─ 落库 messages / conversations（按平台 msg id 去重）
      ├─ 发事件 chats.message（前端会话页实时刷新）
      └─ 通过闸门 → 组装上下文（商品 + 账号 + 全局提示词）→ agents/* 调 LLM
            → services/chats.py::deliver_ai_reply   ← **同一份闸门再判一次**
                → xianyu/im_actions.py 发出去 → 落库 sender='ai:<role>'
```

**生成侧与投递侧共用一份判据**（`_auto_reply_gate`），这是刻意的：任一侧单独放宽，
开关就会漏。

### 4.3 AI 调工具（应用内）

```
主管 AI（master）收到用户一句话
  → agents/tools.py::TOOL_SPECS（148 条声明，每条 {function:{...}, type:'http'}）
  → 模型回 tool_call → _HANDLERS / _SERVICE_TARGETS 找到目标
  → 走同一套 HTTP 路由（**不直连 service**）→ 闸门照样生效
```

### 4.4 DeepSeek Harness 走 MCP

```
DSH → mcp_server/server.py（stdio）→ client.py::TOOL_ROUTES[工具名]
  → {method, path, path_params, query, body} → 本机 HTTP
```

`TOOL_ROUTES` 有 149 条，`canonical_name()` 做别名归一；`_dispatch_route` 会**按声明过滤**
query/body。**新增 MCP 工具必须同时改三处**：`TOOL_ROUTES`、`agents/tools.py` 的声明、
`docs/MCP.md`；漏了会被 `scripts/reconcile_tools.py` 与
`backend/tests/test_mcp_routes_match_openapi.py` 抓住。

## 5. 六条硬口径（改代码前先背下来）

### 5.1 写接口的三道顺序

**确认闸门 → 字段校验 → 构造客户端**，顺序不能换（构造客户端可能触发平台握手，不该在校验失败时发生）。

### 5.2 `confirm` 的坑（真实事故）

`bool('false')` 在 Python 里是 `True`。所以：
- **路由层必须把 `confirm` 原样透传**（`body.get('confirm')`），不许 `bool(...)`；
- **服务层用 `_truthy()` 判**：`True` / 字符串 `'true'`（忽略大小写与空白）/ `1` 才算确认。

历史上 11 条路由 + 10 个服务这么错过，现在有回归测试
`backend/tests/test_write_routes_have_gates.py`（AST 扫描所有写路由）兜底。

### 5.3 统一信封

```json
{"success": true,  "data": {...}}
{"success": false, "message": "中文人话", "code": "机器码"}
```

| HTTP | code | 什么时候 |
| --- | --- | --- |
| 409 | `verification_required` | 登录态失效（同时把 `login_state` 写回 `need_relogin`，前端据此弹重新登录） |
| 409 | `confirm_required` | 写操作没带 `confirm` |
| 502 | `protocol_error` | 平台明确拒绝（如 `FAIL_BIZ_IDLE_USER_UNAUTHORIZED` / `NO_PERMISSION`）——**不回写登录态** |
| 503 | `xianyu_not_ready` | 协议层没这个方法/模块没装好（**注意：也可能是「没实现」**） |
| 404 | `not_found` | 本地没有这条数据（订单/商品 id 找不到） |
| 404 | `route_not_found` | 路径压根没注册 |
| 502 | `protocol_error` + 冷却文案 | 撞上**风控冷却**：`账号处于风控冷却中，还需 Ns` |

### 5.4 `null ≠ 0`

平台**沉默**（不返回该字段）时一律落 `null` + 中文提示，**不要补 0**；补 0 会把「不知道」
伪装成「零」，前端会显示成真实数据。

### 5.5 平台错误要翻成人话

`services/platform_errors.py::PLATFORM_ERROR_HINTS` 是唯一映射表；新增平台错误码时加在这里，
不要在业务代码里就地 `if 'RGV587' in msg`。

### 5.6 AI 回不回：判据只有一处

`services/chats.py::_auto_reply_gate(conversation)`，顺序：

```
全局总开关 ai.enabled
  → 范围 chat.auto_reply_scope（all / items_only / off）
    → 人工接管窗口 chat.human_takeover_seconds（最近一条人工外发消息有多新）
      → 会话模式（mode='auto'）→ 系统消息 → 账号级 auto_reply
```

拒发都有结构化 code：`ai_disabled` / `auto_reply_scope_off` / `auto_reply_scope_items_only` /
`human_takeover` / `mode_not_auto` / `system_message` / `account_auto_reply_off`。
**这三个全局开关此前生产代码一次都没读过（假开关），第五十五批才真正接上。**

## 12. 避坑手册（都是真踩过的）

### Windows / PowerShell

- **`pwsh` 不存在**，只有 Windows PowerShell 5.1。
- **UTF-8 无 BOM 的 `.ps1` 里写中文注释会出事**：5.1 按 ANSI 读，注释行会把**下一行吞掉**
  （症状：脚本里的变量莫名是 `$null`）。要么全英文，要么存成 UTF-8 **带 BOM**。
- **`[System.IO.File]::ReadAllText("相对路径")` 不认 `Set-Location`** —— .NET 用的是进程工作目录。
  一律传绝对路径。
- **`>` 重定向的编码看是谁写的**：`cmd /c "... > log"` 由 cmd 落盘（原始字节，UTF-8）；
  PowerShell 自己的 `>` 是 UTF-16LE。读日志前先确认口径，否则满屏乱码。
- **`python -c "…中文…"` 在内联命令里必被转义搞坏**（ParserError）→ 把脚本写成文件再跑。
- **`Set-Content -Encoding UTF8` 会加 BOM** → 用 `write` 工具写提交消息文件，
  或提交后用 `git commit --amend -F <file>` 修。
- 需要 `PYTHONIOENCODING=utf-8`（+ `sys.stdout.reconfigure`）才不会被 GBK 截断中文。

### 前端

- **`npx tsc --noEmit` 必须在 `frontend/` 里跑**：仓库根目录会解析到另一个 tsc，报一堆假错。
- `npm run build` 的日志是 UTF-16LE。
- **`frontend/dist` 是 gitignore 的**，但打包版复验依赖它 —— 重建前端后一定要重打包。
- **不许删/改 `styles.css` 已有的类名与 `:root` 变量名**（页面靠它们，删了就白屏）。
- **全站零 emoji**：图标一律 `frontend/src/icons.tsx` 里的内联 SVG；新图标往那儿加。
- 主题走 `document.documentElement.dataset.theme`（默认 dark / light），持久化在
  `localStorage['xywb_theme']`；每页一个 css 文件、由该页 import。
- **不许轮询**：用 `useAsync` 第 4 个参数订阅话题。

### 打包

- **打包前必须 `taskkill /IM "闲鱼AI工作台.exe" /T /F`**，否则
  `PermissionError [WinError 32] ... _internal\base_library.zip`。
- `desktop.spec` 用 `collect_submodules('backend')`：**改了 `backend/**` 就得重打包**。
- 打包脚本的 `Get-FileHash` 在受限模式下会失败（§10 第 4 条），**退出码 1 不代表构建失败** ——
  以「exe 时间戳 + `/api/health` 200」为准。

### 测试

- **`unittest.main()` 必须在文件末尾**：写在中间，后面追加的类根本不会跑（假绿）。
- 测试基类里的 `self.fail` 可能被 HTTP 辅助方法遮蔽 —— 症状是断言失败显示成
  `httpx.InvalidURL`，很难认。
- **`app.routes` 不展开 `_IncludedRouter`**：要拿路由清单请用 `create_app().openapi()['paths']`。
- `/api/health` 的 `ok` 在 `data` 里：`{"success":true,"data":{"ok":true,…}}`，别读顶层。
- `send_manual` **成功**响应里也带 `code:'ok'`，别把「有 code」当成失败。
- 断言前记得 `install_client()`（假客户端要先进位）。
- 写补丁脚本时，**幂等标记要按「每一处编辑」打**：用文件级标记会让后面的编辑被静默跳过；
  锚点优先选**唯一且单行**的。

### 真机 / 平台

- 连续探测会触发风控（`FAIL_SYS_USER_VALIDATE; RGV587_ERROR`，外加几十秒冷却）；
  **一次只打一条**，别循环。
- 只读探针也要用 `SAFE_ACC='9999999999999'` 这类不存在的账号走确认腿，**保证零写入**。
- 不要拿真实账号去遍历整个类目树。
- 平台沉默 ≠ 0（§5.4）。
- 平台明确拒绝（`FAIL_BIZ_IDLE_USER_UNAUTHORIZED` / `NO_PERMISSION`）是 **502 `protocol_error`**，
  **绝不能回写 `login_state`** —— 那是权限问题，不是登录问题。
- 会话失效才回写 409 `verification_required` + `need_relogin`。

### Agent / 团队（如果你是让 AI 接手）

- 大任务先拆成 `team_task_create`（写清交付物 + 验收 + 写盘范围 + 预算），
  一步活不要组队。
- 审查要**独立上下文**跑一遍；大任务再补一遍「审那轮审查本身」。
- 批次记录必须带**真实命令与真实输出**；没跑过的结论只能写成「未验证」。
